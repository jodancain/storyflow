# 映序 StoryFlow

## v0.4.2：成片最后再对一遍嘴型

Docker 后期增加 **最终合成 → 逐段口型复核 → 不准片段返修 → 重新合成再审 → 交付**。复核绑定真实影片、母带、时间线及素材哈希；全片各段均须人工通过或说明不适用，技术检测不会自动批准嘴形。私有复核工具保留意见历史，`export-reviewed` 只导出当前通过的成片；不会自动调用模型或发布。步骤与命令见 [编辑器指南](docs/EDITOR-WORKER.md#最终口型复核与返修)。

## v0.4.1：生产性测试与恢复加固

新增真实进程SIGKILL与HTTP供应商账本验证，修复还原中断后误建空库、媒体检查期间取消任务后仍发布候选，以及Linux多段AAC拼接丢音的问题。主应用和独立编辑器分别做Docker验收，更新已失效的Chromium固定版本；范围、恢复命令和放行规则见 [生产性测试](docs/PRODUCTION-TESTING.md)。源码发布与实际生产切换分别记录。

## v0.4.0：声音先行，独立 Claude Code 后期

面向故事化医学科普的独立应用：**需求／本体 → 展开 → 审核 → 视频**。本版将已实际走通的制作方法整理为可跨 Mac 交接的完整源码包，包含应用、独立编辑器 Docker、锁文件、带图示例、本体方法、测试和部署模板。默认医学模板为 **60 秒／25fps／1500 帧／1080×1920**，也支持 24fps。

工作流为：**脚本与资产审核 → 完整声音听审 → 用同一音轨制作医生口型 → 冻结素材 → Docker 内 Claude Code 编程剪辑 → 独立检测 → 公网审片**。Claude Code 经原生 9Router 请求 `ezr/claude-opus-5-5`，真实查看检查图、编写程序并执行 FFmpeg。普通应用仍只接受受校验的结构化模型输出；代码执行限定在独立编辑器的隔离环境。

- [完整工作流及框图](docs/VOICE-FIRST-WORKFLOW.md)：每步输入、输出、审核和返修范围。
- [下一支影片交接模板](docs/templates/EDITOR-BRIEF.md)：不带真实媒体、凭据或历史批准。
- [编辑器配置与任务恢复](docs/EDITOR-WORKER.md)：9Router、Docker、输入哈希与受理不明处理。
- [完整源码打包与核验](docs/SOURCE-RELEASE.md)：从指定 Git 提交打包，避免混入工作区和私有运行数据。

应用任务与独立编辑器之间目前由操作者冻结、提交和回收产物，**尚未做成网页自动联动 API**。已有 V8.3 影片验证了实际后期工具执行及严格60秒输出；内容连续性、声音自然度和医学审片分别保留人审。源码发布不改变已运行服务，不触发新的模型调用。应用未来独立地址仍为 `https://storyflow.yundongyl.cn`，云动现有审稿服务和独立编辑器的历史上线记录见交接文档。

## v0.3.2：图片采用与视频审片（历史交付）

在线审稿页的“生成逻辑”区可查看真实视频任务、播放与下载候选。管理员核对当前候选后通过，后台继续已经排队的后续镜头；医生声音通过后才制作同音轨口型。不通过不会自动重投，未创建任务时明确显示尚未开始。

新增 `POST /api/projects/:id/production-images/adopt`，按明确列出的已批准展示候选，一次性绑定制作资产和首帧。修复相同图片从预览转入制作后被误判为过期的问题，保留原生成哈希和回执，独立记录采用证据。采用图片、批准制作快照、提交任务仍分别保存，不能把网页未提交的勾选或后续声音当成已批准。

公开播放仅限明确公开工程中真实已完成任务的产物；上传原照、私有文件和供应商回执不会因此公开。详细验收见 [验收记录](docs/VERIFICATION.md)。

本仓库与原视频工作台独立。v0.1～v0.3 的交付记录保留，各版本的图片、部署与验收状态见 [验收记录](docs/VERIFICATION.md)；历史章节的“本轮”只指该次交付。

## v0.3 的直接审图与人物一致性

图片下直接选择“通过 / 不通过”并填写评论，点击“提交意见并生成返修图”。通过只保存人工审核；不通过会保存意见并为该图创建一次返修任务。角色基准先通过，包含该角色的后续镜头强制引用同一张批准图；身份、发型、服装状态和允许入镜的人物分别记录。

旧50张候选继续保留并明确标为旧版待核对，不能把新增约束当作这些旧图已经满足一致性的证据。本次升级没有自动重生成图片、视频或声音。

在线审稿使用常驻后台和管理员登录，匿名分享者只读。未连接后台的离线快照明确提示不可提交；意见文件导出已移出主交互。部署范围、接口和验收边界见 [v0.3审图流程](docs/REVIEW-WORKFLOW-v0.3.md)。

## v0.2 的图片审稿流程（历史交付）

打开项目后先看到当前影片、真实图片进度、待处理任务与下一步。四阶段入口保留，行动卡可直接到图片审稿。交互借鉴养成系项目的“进行中的事”和“行动卡直达”；浅色、靛紫、统一圆角与克制动效是本项目实现，不包含 SAI 内部文档、截图、品牌素材或用户画像。

1. 在 **审核 → 资产图与首帧** 查看专属资产和逐镜构图。网络照片在“来源与形态依据”内，不能代替最终资产。
2. 配置图片服务后，先核对“实际发送的参考图”，可取消默认选中的关联资产，再按目标明确提交一个新候选。保存请求模型、实际回传模型、父图及内容哈希；无凭据显示待配置，不伪造结果。
3. 放大、并排比较、记录意见并人工审核。生成成功、技术需返修、人工定稿是不同状态。
4. **作为审稿展示图**只更新展示；**采用为制作资产／视频首帧**必须是当前条件下已通过的候选，并使相关镜头重新待审。浏览或比较图片不会修改视频输入。
5. 用项目顶栏“导出公开审稿包”下载固定快照，可独立托管给他人审稿。本地意见可下载 JSON，再导入另一台 Mac 的工程；原图片哈希和意见来源保留，导入不会直接批准服务器中的制作任务。

本轮 V6 的目标是32项专属资产图＋20镜预定首帧，单目标一次候选、最多52次生图提交，不自动重跑。`A-SYM-FOAM` 已被供应商 `moderation_blocked` 拒绝，依赖它的 `S06` 未提交；保留真实缺口。已完成50张候选（31项资产＋19镜首帧），人工定稿0张；其中16项有技术返修建议；检查记录不能当作人工批准。

## 在另一台 Mac 开发

源码按 Apple Silicon 与 Intel 的跨 Mac 开发设计；本次验证不是所有平台的实机验收。主应用使用 Node 22.13+（建议 `.nvmrc` 对应版本）、Python 3、FFmpeg 和 Chromium／Chrome，无需原项目目录、原电脑用户名或 Docker。独立编辑器另需 Docker/Linux 沙箱，见其专用指南。

```bash
git clone git@github.com:jodancain/storyflow.git
cd storyflow
npm ci
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
# .env 设置 PYTHON=.venv/bin/python；已安装 FFmpeg 时可保留默认命令名。
npx playwright install chromium
npm run doctor
npm run build
npm start
```

打开 `http://127.0.0.1:18296`，首次设置至少 12 位管理员密码。开发 UI 时保持 API 运行，在另一个终端执行 `npm run dev:ui`，打开 `http://127.0.0.1:18297`。修改服务端代码后重启 API。

媒体与 SQLite 默认写到 `~/.local/share/storyflow`，不在 Git 或同步盘内。可通过 `STORYFLOW_DATA_DIR` 更换为本机持久目录。不要把活动数据库放到 iCloud、NAS SMB 或其他同步目录。只能运行一个工作进程。

无模型凭据即可创建需求、解析资料、导入包含待审图片的模板、编辑本体、查看框图、比较候选、审核、导入已有视频／声音、合成和导出工程。模型任务明确显示“待配置”。配置方式见 [.env.example](.env.example) 和 [部署文档](docs/DEPLOYMENT.md)。密钥不进入浏览器、源码或项目包。

## 操作流程

1. **需求**：填写主题、受众、时长、画幅和医生方式。导入 ZIP、PDF、DOCX、文本及参考图。扫描 PDF 提示补充可读文本；不会编造 OCR 内容。
2. **展开**：导入狼疮 V6 示例或调用已配置的 Opus。编辑人物、关系、镜头、台词、医学来源和素材对应关系，运行校验与编译。可检索 PubMed／Wikimedia Commons 并登记来源；检索条目不等于已获成片使用许可或已下载素材。
3. **审核**：逐镜与逐素材保存意见。批准绑定当前内容哈希；相关修改自动使旧批准失效。图示和字幕有独立后期审核。导入的历史意见保留为待确认，不自动批准新工程。
4. **视频**：按当前审核快照提交全片或单镜。照片医生先准备并审核声音，再交已选 fal／火山 OmniHuman 1.5 制作同音轨口型。完整声音先行的叙事片按新工作流先冻结母带、逐句时间和医生驱动音轨，再制作口型与后期。候选产物审核后选择入剪；素材不足报出缺口，不自动循环补齐。

原片、声音与来源哈希始终保留。单改字幕只需重新审核相关内容和合成，视频生成哈希不变。导入已有音轨并审核后，照片医生任务可直接复用同一音轨。平台无法自动判断医学正确性、嘴形自然度或叙事表现，最终内容仍须审片。

## 模型与执行边界

| 职责 | 当前实现 | 真实验证状态 |
|---|---|---|
| 故事／虚构医生视频与声音 | Seedance 首帧／文本适配器，单段上限12秒；另有冻结 Veo 协议 | 模拟协议与历史素材记录分开；本次源码发布不新生成 |
| 指定照片医生口型 | fal／火山 OmniHuman 1.5；冻结同一已审音轨 | 火山五段新版口型已用于 V8.3；不据此推断 fal 效果或人审通过 |
| 专属资产与分镜图片 | 独立 OpenAI 兼容图片适配器，默认请求 `gpt-image-2` | 有真实历史候选；回传模型缺失保持未知，旧图不自动批准 |
| 本体展开与后期图示 | Anthropic Messages 兼容接口，结构化 JSON／声明式方案 | 有历史真实图示及可信渲染；医学内容仍需审核 |
| 应用内合成 | Chromium 受限声明式绘制 + FFmpeg | 固定媒体、字幕、帧数、音轨与完整解码测试 |
| 独立 Claude Code 后期 | `ops/editor/`，原生9Router＋隔离MCP＋Python／Node／FFmpeg | 已实际看图、写程序和执行60秒成片；不是仅返回剪辑建议 |

模型名由部署者按供应商实际可用名称配置。`OPUS_MODEL` 默认值仅是预设，不代表该账户已开通。应用不执行任意模型代码；独立编辑器只在已声明输入和任务工作区内执行获授权的后期程序。网关回传模型名是回执，不能独立证明上游身份。当前 Seedance 只发送首帧；尾锚图是审稿目标，不能称为已传入动作控制。

所有外部提交先保存意图和请求哈希。重启续查已受理任务；受理不明时停止自动重投，可核对供应商任务 ID 后恢复。取消仅停止本地跟进，不能承诺供应商退款。后台执行不依赖浏览器保持打开。

### 独立图片服务配置

`.env` 中填写 `IMAGE_BASE_URL`、`IMAGE_API_KEY`、`IMAGE_MODEL`。base URL 按供应商约定包含 `/v1`；默认请求模型为 `gpt-image-2`。图片凭据与 Opus、Seedance、fal 独立，密钥不进入浏览器或示例。模型名只是请求参数，界面另列供应商实际回传值，缺失时显示“未回传，不推断”。详情及恢复语义见 [开发交接](docs/HANDOFF.md)。
