# V6 可编辑示例与真实图片候选

`lupus-v6.json` 是《那个没系完的结》的医学故事草稿：20镜、25fps、60秒、9:16。示例保留人物、道具、事实依据、症状对应、动作衔接与医生同步路线；没有本轮新视频、声音或已经通过的口型。

## 资产与来源

本体原有52个专属槽，其中32项为角色、场景、道具、症状或图示等专属资产，20项为动态底片输出；另有12项允许分发的网络参考，共64条资产。v0.2 为20个镜头单独增加预定首帧图片候选，首帧图片并不把视频输出槽变成已经生成的视频。

`lupus-v6.assets.json` 使用相对路径与 SHA-256 注册资产；图片候选清单同样校验内容哈希后注册成新工程的待审候选，实际绑定使用新工程文件 ID。网络参考的署名与许可保留在 `assets/CREDITS.json`，仅作来源/形态依据。库存诊室人物、网络症状照片不能冒充本片人物或制作图。

本轮目标32项资产＋20镜首帧，每目标先提交一个候选。`A-SYM-FOAM` 已被供应商 `moderation_blocked` 拒绝；`S06` 因该前置缺失未提交，不自动重试或用别图顶替。当前实际50张候选（31项资产＋19镜首帧），人工定稿0张，其中16项有技术返修建议。技术问题见 [验收记录](../docs/VERIFICATION.md) 及同版本交付清单；所有候选尚需人工定稿，示例加载不会自动批准。

照片类图片的请求模型为 `gpt-image-2`，实际模型在供应商没有回传时保留空值。医学图示由真实 Opus 调用输出受限声明式方案后渲染，不执行模型任意代码。原生成图、必要的9:16派生图及裁切/父图哈希记录分开保留，不能拉伸人物来适配画幅。

## 审稿与继续制作

进入“审核 → 资产图与首帧”放大、比较、记录意见。候选批准后仍需明确选择“采用为制作资产”或“采用为视频首帧”。“作为审稿展示图”只影响页面展示，视频输入保持原绑定；与图片相关的镜头按依赖重新待审。

导入公网导出的 JSON 意见时，核对本体快照、目标和候选图片 SHA-256。跨 Mac 工程 ID 变化不会丢失意见来源；内容或图片不匹配的条目保留为历史。网页里的“通过”不会绕过本机正式审核。

本次授权的指定医生 AI 派生图可以随示例进入私有 GitHub、源码 ZIP 和既有公网审稿页，人物仍须人工核对。指定医生原照、私人资料包、原始凭据、旧视频和内部生产记录不打包。新 Mac 无需原电脑目录；加载模板不代表批准后续模型费用。
