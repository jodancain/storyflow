# 人物一致性与图片返修契约

用户要求同一人物在整片中保持一致。v0.3 将它变成可验证的输入约束和人工审核顺序，不把提示词或模型成功回执当作画面一致性已经通过。

## 先定角色，再制作其他画面

1. 四张角色基准分别为女主、医生、朋友手袖和检验人员手袖。每个角色只能有一个当前通过的候选。
2. 先在基准卡上人工通过。未通过时，依赖该人物的症状、动作和分镜返修保存意见并显示等待原因，不提交模型。
3. 下一张图片强制把对应已审基准文件放在参考列表最前面，记录实际文件 ID、SHA-256、批准候选和角色对应关系。前端取消其他参考不会移除这些身份图。
4. 参考房间、道具或上一镜不能成为第二套身份来源。发现带未声明人物的参考，或该参考仍有技术返修问题时，阻止把它用于当前镜头。
5. 通过新的基准后，旧基准保留历史；下游仍引用旧基准哈希的产物需要重新核对，不能继续标成当前一致性输入。

本轮升级不自动重跑旧的50张候选，也不自动批准其中任何一张。旧候选可以打开检查和提出意见；没有真实新合同回执的旧图，不得仅因为导入时换了本体哈希而显示为“按新人物合同生成”。

## 类型与校验

`Ontology.imageConsistency` 为可选的版本1字段，旧工程不带此字段时保持兼容。启用时包含 `enforceApprovedIdentity: true` 和 `characters`：

- `characterId`：现有角色实体 ID。
- `identityAssetId`：专属制作图片资产 ID；不同角色不可共用。
- `visibility`：`person` 或 `hands-only`。
- `appearance`：固定外貌与不可更改的发型、发色等特征。
- `wardrobes`：具名服装状态；服装变化不创建新人物身份。

所有制作图片资产与镜头必须有 `imageComposition.visibleCharacters`。每项声明角色、服装状态、可见范围（脸、身体、手袖或肩背）。空数组就是空场景或独立物件，不能默认增加一个背景人物。`hands-only` 角色不能被改成露正脸；镜头可见人物必须同时存在于 `entityIds`。

校验拒绝未知角色、资产、服装，重复角色，混用身份图，遗漏构图合同与无效字段。身份特征、服装和构图进入生成／审核哈希；只改字幕不使视频生成输入失效。

| 角色 | 基准 | 使用范围 |

| 女主 | `A-CHAR-P01` | S01–04、S07–08、S13、S15–20；诊室保持披发与米白衣；S18–20持续穿同一防晒外套 |

## 可调用模块

`shared/image-consistency.ts` 是无网络、无存储写入的纯模块：

- `validateImageConsistency(ontology)` 返回带路径的错误，不静默修改草稿。
- `resolveImageConsistency(ontology, targetId)` 返回角色白名单、强制身份资产、服装与不可被补充意见替代的提示段。
- `inspectImageConsistency(project, targetId, requestedReferenceAssetIds)` 返回真实已审身份文件、优先级确定的参考 ID、错误和 `ready`。

状态需要分别显示：意见已保存、身份基准待审、真实任务排队／执行、生成候选待审、人工通过。文件解码成功、技术测试通过不等于人物已被人工确认为一致。

拒绝代码包括 `identity_not_approved`、`identity_selection_ambiguous`、`reference_actor_conflict`、`reference_needs_revision` 与 `provider_policy_blocked`。最后一项保留政策拒绝，不因用户一般返修意见而改词或换模型重投。

## 验证

`npx tsx --test tests/image-consistency.test.ts tests/ontology.test.ts` 验证兼容性、角色与服装引用、单一已审基准、旧预览不覆盖新基准、含错人物的参考被阻止、字幕与生成哈希分离、政策拒绝和V6全部目标映射。供应商是否实际保持面容一致仍需检查真实产物。

## 指定真实人物的原照门禁

`CharacterIdentity.referenceSourceAssetId` 可指定必须使用的原始授权照片。它必须引用独立的 `reference` 图片资产，不能指向角色基准自身、生成候选、文档或另一张制作图。

V6 的医生使用 `A-CHAR-D00-SOURCE` 空槽。交付代码只带槽定义，原始医生照片仍不进入源码、示例和公网。用户在私有工作区导入原照并人工核对后，医生基准的返修才可提交。没有原照时保存意见并显示 `identity_source_missing`；原照尚未审核显示 `identity_source_not_approved`；把AI派生图绑定为原照显示 `identity_source_not_original`。没有文字生成医生的回退路径。

创建医生基准时，原照成为第一张实际参考，记录 `role: source`、文件ID与SHA-256。之后其他镜头只使用人工批准的医生基准派生图；不要求把私人原照发送到每个镜头，也不能因此把原照公开。已交付的旧医生候选仍可人工审核，在没有原照的另一台Mac上通过该派生图后，仍可用于下游分镜。
